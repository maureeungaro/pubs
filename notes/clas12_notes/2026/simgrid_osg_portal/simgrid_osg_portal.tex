\begin{noteabstract}
simGrid is the self-service web portal through which the CLAS12 collaboration submits GEMC
Monte-Carlo simulation workflows to the Open Science Grid (OSG). A collaborator selects a detector
configuration, an event generator or a directory of pre-generated LUND files, magnetic-field settings,
and software versions; the portal turns that choice into a steering card, stages it through a MySQL
database, and a submission engine converts it into an HTCondor cluster that executes on opportunistic
OSG slots inside the CLAS12 Singularity container. Each worker node runs the full CLAS12 chain ---
generator, GEMC, background merging, denoising, reconstruction, and DST creation --- and writes the
result back to Jefferson Lab volatile storage through the OSDF/Pelican data federation. Because every
job runs under a single shared HTCondor owner (\texttt{gemc}), the portal implements two deliberately
separate fair-share mechanisms: a database-side pending queue that orders not-yet-submitted requests
across users, and a runtime HTCondor \texttt{JobPrio} map that balances running jobs across
already-submitted clusters. This note documents the architecture, the data and submission-state
models, the generated HTCondor and worker-node scripts, both priority systems, and the operational,
testing, and security practices that make the system reproducible and fair.
\end{noteabstract}
